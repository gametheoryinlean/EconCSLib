# Complexity-model audit for the EconCS open problems

## Reference corpus

The local OpenAI `ten-proofs` checkout contains the ten main developments
`SpherePacking`, `MetricCodes`, `Permanent`, `NonSoficGroup`,
`ConnesRigidity`, `EhrhartVolumeInequality`, `QuantumParallelRepetition`,
`GapCVP`, `MulticolorTriangleRamsey`, and `CompactnessAndDegeneracy`.

Only two contain transferable *computational-complexity* design patterns:

- `GapCVP.lean` fixes lossless encodings before the Turing-machine witness,
  stores a finite machine and an explicit `Polynomial ℕ`, bounds the actual
  execution, and proves an output-length bound before composing machines.
- `Permanent.lean` represents an arithmetic circuit by a finite instruction
  list and measures its size syntactically.

Occurrences of the mathematical word “polynomial” in the other eight files
are not polynomial-time certificates and are intentionally not imported into
the RAM model.

## Accepted unit-cost RAM convention

The strict EconCS model is the instruction interpreter in
`UnitCostRAMMachine.lean`:

1. exact integers, exact reals, and Booleans occupy one word;
2. permitted scalar arithmetic/comparison, addressing, and branching cost one
   local step;
3. allocating or freeing `k` heap cells costs `k + 1` steps, and a
   variable-length input/output/oracle transfer costs its number of words;
4. oracle calls, samples, random bits, and peak cells have separate counters;
5. input/output encodings and external-oracle semantics are fixed before the
   program witness;
6. the certificate contains one finite program and an explicit natural
   polynomial bounding the actual interpreter execution;
7. an indexed family is uniform only when one program receives the index as
   part of its encoded input.

This is an exact-real/unit-cost RAM convention, not Turing bit complexity.
Any theorem about bit complexity must use a binary representation and a
bit-sensitive arithmetic model.

## Status of the interfaces

### Machine-enforced

- `StrictRAMComputableInPolyTime`
- `StrictRAMComputableInPolyTimeWithFixedEnvironment`
- `StrictRAMSearchableInPolyTime`
- `FixedEncodingSearchProblem`
- `FixedEncodingPolynomialSearchReduction`
- `FixedEncodingFunctionFamily`
- `StrictPPADHard`, when both End-of-Line and the target search problem supply
  canonical encodings

### Structurally meaningful independent resources

- recursive query counts generated by a finite query tree;
- transcript/message lengths generated by a protocol syntax, with the unit
  explicitly declared as bits or exact RAM words;
- interpreter-generated random-bit, sample, query, and peak-space counters.

### Trusted instrumentation only

- `CostedImplementation`, `ProfiledRAMImplementation`, and predicates built
  solely from their writer-monad counters;
- `localCost` fields attached by hand to a query-tree continuation;
- `PolynomialSearchReduction` and the original `PPADHard` compatibility name.

These are useful for compositional proofs and static analysis, but cannot by
themselves define a complexity class: a Lean computation could be hidden in
`Cost.pure`, `Cost.map`, a callback, or a witness-local external environment.

The compatibility names remain available for older clients, but none of the
24 current `Problem.lean` statements relies on a vacuous complexity predicate.
That observation does **not** make all 24 problems algorithmic: several are
pure existence or extremal questions, and several use a query model in which
local computation is intentionally free.

## Binary confidence classification of all 24 benchmarks

Directory prefixes now have one meaning only:

- `1_` means that the Lean statement is judged faithful to the Markdown after
  checking its data, quantifier order, main conclusion, and any advertised
  resource model.
- `3_` means that a material model or representation question remains.  A
  file may compile successfully and still belong here.

The ordinary human requirement that a numerical answer be informative rather
than a renamed extremum does not by itself cause a `3_` classification.

## Conclusions and model boundaries

- The five structural resource interfaces (deterministic communication,
  Tarski queries, multi-unit value queries, truthful-submodular demand queries,
  and Robertson--Webb queries) measure the resource requested by their source
  problem.  They deliberately do not certify local running time.
- The strict migrations tie program output and every advertised resource bound
  to an interpreter execution.  A callback, an arbitrary seed law, or a
  writer-monad counter is no longer sufficient evidence for those statements.
- Exact-real words are a declared modeling choice.  In particular, the PCP
  statement requires a separate bit-model formalization or a transfer theorem
  before it may be cited as classical Turing-model PPAD-hardness.
- Lean can check that a supplied number, rate, or characterization satisfies a
  correctness predicate.  It cannot in general check that the submission is a
  useful closed form rather than a renamed `sInf`/`sSup`, or that an abstract
  description language is mathematically illuminating.  Those residual cases
  are intentionally left to human review.

No semantic open-problem answer is changed by this audit.  The classification
only records whether a resource claim is tied to a concrete operational model
and where an unavoidable representation or explicitness judgement remains.
